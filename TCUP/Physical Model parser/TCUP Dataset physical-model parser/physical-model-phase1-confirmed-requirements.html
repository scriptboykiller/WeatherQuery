Physical Model 第一阶段需求基线

本文展示目前已经确认的第一阶段范围：从 JSON、XML、JSON Schema 和 XML Schema（XSD） 中提取业务结构的叶子 Attribute Path。本文是已确认需求，不包含待确认的问题。

4支持的输入格式
Leaf Only仅输出叶子属性
.统一路径分隔符
[]数组/重复结构标记

第一阶段目标 MVP

JSON / XML / Schema 输入
→
解析业务层级结构
→
输出叶子 Attribute Path

目标不是简单展平文件本身，而是识别文件所表达的业务字段。例如 JSON Schema 中的 properties、XSD 中的 complexType 都不会成为输出路径。

支持的四种输入 Confirmed

JSON

从实际 JSON 数据结构中提取已经出现的叶子字段。

XML

从实际 XML 元素层级中提取叶子元素，并保留根元素。

JSON Schema

根据 Schema 描述的业务 properties/items 提取字段。

XML Schema / XSD

根据 XSD 的业务 element、complexType 和重复关系提取字段。

通用规则 所有格式适用

1

只输出叶子属性

对象、复杂元素和包装节点只参与组成路径，不单独输出。

2

路径使用点号连接

统一格式为 parent.child.attribute。

3

数组使用 []

简单数组为 emails[]；对象数组为 items[].id。

4

不输出空对象节点

例如 JSON 的 { "data": {} } 不产生 data 属性。

5

当前只关注 Attribute Path

第一阶段不要求保存实际值。

6

暂不输出类型

string、integer、boolean 等类型不属于当前输出。

7

暂不输出约束

required、enum、长度和数值范围不进入结果。

8

null 仍可产生 Attribute

即使类型无法判断，只要字段名存在，就可以输出路径。

9

忠实保留原始结构

当前不做 JSON 与 XML 之间的命名或层级归一化。

10

完整路径是唯一标识

同名叶子出现在不同父路径下时，属于不同 Attribute。

JSON 已确认规则 实例数据

对象、简单数组与对象数组

已确认
输入 JSON
{
  "user": {
    "name": "Ava",
    "emails": ["a@x.com", "b@x.com"]
  },
  "items": [
    {"id": 1, "price": 10},
    {"id": 2, "price": 20}
  ]
}
输出 Physical Attributes
user.name
user.emails[]
items[].id
items[].price
JSON 不添加 root 等虚拟根节点。

null 与空对象

已确认
输入 JSON
{
  "employeeId": null,
  "data": {}
}
输出
employeeId
employeeId 虽然类型未知，但字段名确定；空对象 data 不产生叶子属性。

XML 已确认规则 实例数据

保留根节点与嵌套元素

已确认
输入 XML
<appConfig>
  <appName>dqma-cicd</appName>
  <environment>local</environment>
  <featureToggle>
    <localRun>true</localRun>
  </featureToggle>
  <retryCount>3</retryCount>
  <owners>
    <owner>dataops-team</owner>
  </owners>
</appConfig>
输出
appConfig.appName
appConfig.environment
appConfig.featureToggle.localRun
appConfig.retryCount
appConfig.owners.owner
XML 的真实根元素 appConfig 必须保留。当前不把 XML 命名转换为 JSON 的 snake_case。

重复 XML 元素

基础规则已确认
输入 XML
<owners>
  <owner>team-a</owner>
  <owner>team-b</owner>
</owners>
输出
owners.owner[]
重复出现的元素使用 []。是否仅出现一次时也标记为数组，仍属于单独待确认问题。

JSON Schema 已确认规则 Schema 语义解析

properties、object 与 array

已确认
输入 JSON Schema（简化）
{
  "title": "AppConfig",
  "type": "object",
  "properties": {
    "app_name": {"type": "string"},
    "environment": {"type": "string"},
    "feature_toggle": {
      "type": "object",
      "properties": {
        "local_run": {"type": "boolean"}
      }
    },
    "retry_count": {"type": "integer"},
    "owners": {
      "type": "array",
      "items": {"type": "string"}
    }
  }
}
输出
app_name
environment
feature_toggle.local_run
retry_count
owners[]
不输出 $schema、$id、title、type、 properties、items、required 和约束值。

XML Schema / XSD 已确认规则 Schema 语义解析

complexType、simpleType、sequence 与 maxOccurs

已确认
输入 XSD（简化）
<xs:element name="appConfig">
  <xs:complexType>
    <xs:sequence>
      <xs:element name="appName" type="xs:string"/>
      <xs:element name="featureToggle">
        <xs:complexType>
          <xs:sequence>
            <xs:element name="localRun"
                        type="xs:boolean"/>
          </xs:sequence>
        </xs:complexType>
      </xs:element>
      <xs:element name="owners">
        <xs:complexType>
          <xs:sequence>
            <xs:element name="owner"
                        type="xs:string"
                        maxOccurs="unbounded"/>
          </xs:sequence>
        </xs:complexType>
      </xs:element>
    </xs:sequence>
  </xs:complexType>
</xs:element>
输出
appConfig.appName
appConfig.featureToggle.localRun
appConfig.owners.owner[]
不输出 schema.complexType.sequence 等 XSD 语法路径。 maxOccurs > 1 或 unbounded 会影响 []，因此需要读取，但不作为约束输出。

第一阶段输入与输出边界 Scope

第一阶段包含

  • 识别四种输入格式的业务结构
  • 提取叶子 Attribute Name / Path
  • 支持对象、嵌套结构和数组
  • 保留 XML / XSD 根元素
  • JSON 不添加虚拟根
  • 解析影响路径结构的信息，如 JSON Schema items、XSD maxOccurs

第一阶段暂不包含

  • 实际值输出
  • 字段类型输出
  • required、nullable、enum、长度和范围等约束输出
  • JSON/XML 跨格式命名归一化
  • 尚未确认的 XML Attribute、复杂 Schema 组合及跨文件引用

第一阶段一句话定义

将 JSON、XML、JSON Schema 和 XML Schema 所表达的树形业务结构， 转换为以点号连接的叶子 Attribute Path 集合；JSON 不增加虚拟根， XML/XSD 保留真实根元素，数组或重复结构使用 [] 表达，并且当前不输出实际值、字段类型和约束。
